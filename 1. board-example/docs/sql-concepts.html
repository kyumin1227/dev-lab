SELECT 쿼리,
어떻게 작성하는가

쿼리를 구성하는 각 절의 역할과 작성 순서를 이해합니다. 모든 예시는 우리 게시판 DB(board.db)에서 직접 실행할 수 있습니다.

sqlite3 board.db users · posts · comments seed.sql 적용 후 실행
1

SELECT 기본 구조

쿼리를 구성하는 6가지 절(clause)

SELECT 쿼리는 최대 6개의 절로 구성됩니다. SELECT와 FROM만 필수이고 나머지는 필요할 때만 씁니다.

SELECT 전체 구조 
SELECT   컬럼1, 컬럼2, ...      -- ① 가져올 컬럼 (필수)
FROM     테이블명              -- ② 어느 테이블에서 (필수)
WHERE    조건                  -- ③ 행 필터링 (선택)
GROUP BY 기준컬럼             -- ④ 그룹화 (선택)
HAVING   그룹 조건             -- ⑤ 그룹 필터링 (선택)
ORDER BY 정렬기준             -- ⑥ 정렬 (선택)
LIMIT    n                     -- ⑦ 개수 제한 (선택)
SELECT
가져올 컬럼을 지정합니다. *는 전체 컬럼, 테이블.컬럼으로 출처를 명확히 할 수 있습니다.
필수
FROM
데이터를 가져올 테이블을 지정합니다. JOIN이 있으면 이 절에서 테이블들을 연결합니다.
필수
WHERE
조건에 맞는 행만 남깁니다. GROUP BY 이전에 실행되므로 집계 결과를 조건으로 쓸 수 없습니다.
선택
GROUP BY
지정한 컬럼 기준으로 행들을 그룹으로 묶습니다. 집계 함수(COUNT, SUM 등)와 함께 씁니다.
선택
HAVING
GROUP BY로 만들어진 그룹에 조건을 겁니다. 집계 결과(COUNT, SUM 등)를 조건으로 쓸 수 있습니다.
선택
ORDER BY
결과를 정렬합니다. ASC(오름차순, 기본값), DESC(내림차순).
선택
LIMIT
반환할 행의 최대 개수를 제한합니다. OFFSET n과 함께 쓰면 페이지네이션이 가능합니다.
선택

게시판 예시 — 가장 단순한 것부터

▶ 실행 예시 — 전체 유저 조회
SELECT id, username, created_at
FROM   users;
→ users 테이블의 모든 행, id·username·created_at 3개 컬럼 반환
▶ 실행 예시 — 최근 5개 게시글
SELECT   id, title, created_at
FROM     posts
ORDER BY created_at DESC
LIMIT    5;
→ 가장 최근에 작성된 게시글 5개 반환
💡

SELECT *는 가급적 피하세요. 필요한 컬럼만 명시하면 네트워크 전송량이 줄고, 어떤 데이터를 쓰는지 코드를 읽는 사람이 바로 알 수 있습니다. users 테이블에서 SELECT *를 쓰면 비밀번호 해시도 함께 반환됩니다.

실행 순서

작성 순서와 실행 순서는 다르다

SQL은 작성하는 순서와 실행되는 순서가 다릅니다. 이 차이를 이해하면 "왜 WHERE에서 SELECT 별칭을 못 쓰는가" 같은 의문이 해결됩니다.

3

컬럼 선택·별칭

⚠️

SELECT가 5번째로 실행됩니다. 따라서 WHERE절(2번째)에서는 SELECT에서 만든 별칭(AS)을 사용할 수 없습니다. ORDER BY는 6번째라 SELECT 별칭 사용이 가능합니다.

실행 순서가 중요한 이유 — 예시

WHERE에서 SELECT 별칭을 쓰면 오류 발생 
-- ❌ 오류: WHERE은 SELECT보다 먼저 실행되므로 별칭을 모름
SELECT COUNT(id) AS cnt
FROM   comments
WHERE  cnt > 5;        -- cnt는 아직 정의되지 않음

-- ✅ 올바른 방법: 집계 결과 조건은 HAVING에 작성
SELECT   post_id, COUNT(id) AS cnt
FROM     comments
GROUP BY post_id
HAVING   COUNT(id) > 5;
▶ 실행 예시 — 댓글이 2개 이상인 게시글만 조회
SELECT   post_id,
         COUNT(id) AS comment_count
FROM     comments          -- ① 테이블 선택
--                            ② WHERE 없음 (전체 사용)
GROUP BY post_id           -- ③ 게시글별로 그룹화
HAVING   COUNT(id) >= 2   -- ④ 그룹 중 2개 이상만
ORDER BY comment_count DESC; -- ⑥ 많은 것부터 정렬
→ 댓글이 2개 이상 달린 게시글 목록, 댓글 많은 순 정렬
3

WHERE 조건 작성법

비교·논리·패턴·범위·목록·NULL 처리

WHERE절에는 다양한 연산자를 사용할 수 있습니다. 조건이 true인 행만 결과에 포함됩니다.

비교 연산자

연산자의미게시판 예시
=같다user_id = 1
!= 또는 <>다르다user_id != 1
> / >=크다 / 크거나 같다id > 10
< / <=작다 / 작거나 같다id <= 50
▶ 실행 예시 — user_id가 1번인 게시글만 조회
SELECT id, title, created_at
FROM   posts
WHERE  user_id = 1;
→ alice(id=1)가 작성한 게시글만 반환

논리 연산자 — AND / OR / NOT

▶ 실행 예시 — 여러 조건 조합
-- AND: 두 조건 모두 참인 행
SELECT id, title
FROM   posts
WHERE  user_id = 1
  AND  id <= 50;

-- OR: 둘 중 하나라도 참인 행
SELECT id, title
FROM   posts
WHERE  user_id = 1
  OR   user_id = 2;
→ 첫 번째: alice 작성 + id 50 이하 / 두 번째: alice 또는 bob의 게시글

LIKE — 패턴 검색

%는 0개 이상의 임의 문자, _는 정확히 1개의 임의 문자를 의미합니다.

▶ 실행 예시 — 제목에 "JOIN" 포함된 게시글
SELECT id, title
FROM   posts
WHERE  title LIKE '%JOIN%';     -- 앞뒤 어디든 JOIN 포함
→ "JOIN 완전 정복", "NATURAL JOIN 이해" 등 제목에 JOIN이 들어간 게시글
▶ 실행 예시 — 아이디가 'a'로 시작하는 유저
SELECT id, username
FROM   users
WHERE  username LIKE 'a%';       -- a로 시작하는 모든 아이디
→ alice 반환

BETWEEN — 범위 조건

ℹ️

BETWEEN a AND b는 a 이상 b 이하(양 끝값 포함)입니다. WHERE id >= 10 AND id <= 20과 동일합니다.

▶ 실행 예시 — id가 10~20 사이인 게시글
SELECT id, title
FROM   posts
WHERE  id BETWEEN 10 AND 20;
→ id 10, 11, 12 ... 20인 게시글 11개 반환
▶ 실행 예시 — 2024년 2월에 작성된 게시글
SELECT id, title, created_at
FROM   posts
WHERE  created_at BETWEEN '2024-02-01' AND '2024-02-29 23:59:59';
→ 2024년 2월 한 달간 작성된 게시글 반환

IN — 목록 조건

IN (값1, 값2, ...)은 목록 중 하나와 일치하는 행을 반환합니다. OR를 여러 번 쓰는 것보다 간결합니다.

▶ 실행 예시 — 특정 유저들의 게시글
SELECT id, title, user_id
FROM   posts
WHERE  user_id IN (1, 3, 5);    -- alice, carol, eve의 게시글
→ alice·carol·eve 세 명이 작성한 게시글 반환 (OR 3개와 동일)

IS NULL / IS NOT NULL

⚠️

NULL은 = NULL로 비교하면 안 됩니다. NULL은 "값이 없음"이므로 비교 결과가 항상 unknown입니다. 반드시 IS NULL 또는 IS NOT NULL을 사용합니다.

▶ 실행 예시 — 개념 확인 (게시판 테이블엔 NULL 없음)
-- NULL 비교의 올바른 방법
SELECT id, username
FROM   users
WHERE  created_at IS NOT NULL;  -- created_at이 있는 유저

-- ❌ 잘못된 방법 (항상 0행 반환)
-- WHERE created_at = NULL
→ created_at이 있는 모든 유저 (게시판에선 전체 유저)
4

JOIN 원리

여러 테이블의 데이터를 하나로 합치기

게시글 테이블에는 작성자 user_id(숫자)만 있습니다. 화면에 이름을 보여주려면 users 테이블과 JOIN해서 가져와야 합니다.

JOIN 기본 문법 
SELECT ...
FROM   테이블A
JOIN   테이블B ON 테이블A.연결컬럼 = 테이블B.연결컬럼
INNER JOIN
🔵🟣🔴 → 🟣
양쪽 테이블 모두에 매칭되는 행만 반환
게시판에서: 게시글과 작성자가 모두 존재할 때만 결과 포함.
JOIN만 써도 INNER JOIN입니다.
LEFT JOIN
🔵🟣🔴 → 🔵🟣
왼쪽 테이블의 모든 행을 포함, 오른쪽은 없으면 NULL
게시판에서: 댓글이 없는 게시글도 목록에 표시해야 할 때.
RIGHT JOIN
🔵🟣🔴 → 🟣🔴
오른쪽 테이블의 모든 행을 포함, 왼쪽은 없으면 NULL
SQLite는 RIGHT JOIN을 지원하지 않습니다. 테이블 순서를 바꿔 LEFT JOIN으로 대체합니다.
CROSS JOIN (주의)
A×B → 전체 조합
ON 없이 두 테이블의 모든 행을 조합
users 20명 × posts 100개 = 2,000행 생성. 의도하지 않게 발생하면 성능 문제를 일으킵니다.

INNER JOIN — 작성자 이름과 함께 게시글 조회

▶ 실행 예시 — 게시글 + 작성자 이름 (INNER JOIN)
SELECT  posts.id,
        posts.title,
        users.username AS author
FROM    posts
JOIN    users ON posts.user_id = users.id
LIMIT   5;
→ id, title, 작성자 이름 3컬럼 반환 (작성자가 없는 게시글은 제외)

LEFT JOIN — 댓글 수 포함 목록 (댓글 없는 게시글도 포함)

▶ 실행 예시 — 게시글 목록 + 댓글 수 (LEFT JOIN)
SELECT   posts.id,
         posts.title,
         COUNT(comments.id) AS comment_count
FROM     posts
LEFT JOIN comments ON comments.post_id = posts.id
GROUP BY posts.id
ORDER BY comment_count DESC
LIMIT    10;
→ 댓글 수 기준 상위 10개 게시글. 댓글 0개인 게시글은 comment_count = 0으로 포함

3개 테이블 JOIN

▶ 실행 예시 — 댓글 + 게시글 제목 + 댓글 작성자
SELECT  comments.id       AS comment_id,
        comments.content,
        posts.title          AS post_title,
        users.username       AS commenter
FROM    comments
JOIN    posts  ON comments.post_id  = posts.id
JOIN    users  ON comments.user_id  = users.id
LIMIT   5;
→ 댓글 내용, 소속 게시글 제목, 댓글 작성자 이름을 한 번에 조회
5

집계 함수

여러 행을 하나의 값으로 요약하기

집계 함수는 여러 행의 값을 받아 하나의 값으로 줄여줍니다. GROUP BY와 함께 쓰면 그룹별로 집계합니다.

COUNT()
행의 수를 셉니다.
COUNT(*)는 전체 행,
COUNT(컬럼)은 NULL 제외
SUM()
숫자 컬럼의 합계를 구합니다.
NULL은 무시합니다.
AVG()
숫자 컬럼의 평균을 구합니다.
NULL 행은 제외하고 계산합니다.
MIN()
최솟값을 반환합니다.
숫자, 문자, 날짜 모두 가능합니다.
MAX()
최댓값을 반환합니다.
가장 최근 날짜를 찾을 때도 씁니다.
COUNT(DISTINCT)
중복을 제거한 고유 값의 수를 셉니다.
▶ 실행 예시 — 게시판 전체 통계 한 번에
SELECT
  COUNT(DISTINCT users.id)    AS total_users,    -- 총 유저 수
  COUNT(DISTINCT posts.id)    AS total_posts,    -- 총 게시글 수
  COUNT(DISTINCT comments.id) AS total_comments  -- 총 댓글 수
FROM      users
LEFT JOIN posts    ON posts.user_id    = users.id
LEFT JOIN comments ON comments.user_id = users.id;
→ total_users: 20, total_posts: 100, total_comments: 200 (seed.sql 적용 기준)
▶ 실행 예시 — 가장 먼저/늦게 가입한 유저
SELECT
  MIN(created_at) AS first_joined,
  MAX(created_at) AS last_joined,
  COUNT(*)        AS total
FROM users;
→ 첫 가입일, 최근 가입일, 총 유저 수 반환
⚠️

COUNT(*) vs COUNT(컬럼)
COUNT(*)는 NULL을 포함한 모든 행을 셉니다.
COUNT(컬럼명)는 해당 컬럼이 NULL인 행을 제외하고 셉니다.
LEFT JOIN 결과에서 "매칭된 행만" 세려면 반드시 COUNT(컬럼명)을 쓰세요.

GROUP BY & HAVING

그룹별 집계와 그룹 필터링

GROUP BY는 지정한 컬럼의 값이 같은 행들을 하나의 그룹으로 묶습니다. 각 그룹에 집계 함수를 적용해 그룹별 통계를 만듭니다.

GROUP BY 동작 원리

comments 테이블을 user_id로 GROUP BY하면:
GROUP BY 전 (일부)
id user_id
12
23
32
44
→
GROUP BY 후
user_id COUNT(*)
22
31
41
▶ 실행 예시 — 유저별 게시글 수 (많은 순)
SELECT   users.username,
         COUNT(posts.id) AS post_count
FROM     users
LEFT JOIN posts ON posts.user_id = users.id
GROUP BY users.id
ORDER BY post_count DESC;
→ 각 유저의 게시글 수. 게시글이 없는 유저는 0으로 표시

WHERE vs HAVING 비교

구분WHEREHAVING
실행 시점GROUP BY 이전 (개별 행 필터)GROUP BY 이후 (그룹 필터)
사용 가능 조건일반 컬럼 값집계 함수 결과
예시WHERE user_id = 1HAVING COUNT(*) > 5
▶ 실행 예시 — WHERE + GROUP BY + HAVING 함께 쓰기
-- 2024년 2월 이후 가입한 유저 중, 게시글을 5개 이상 작성한 유저
SELECT   users.username,
         users.created_at,
         COUNT(posts.id) AS post_count
FROM     users
LEFT JOIN posts ON posts.user_id = users.id
WHERE    users.created_at >= '2024-02-01'  -- 행 필터: 2월 이후 가입자만
GROUP BY users.id
HAVING   COUNT(posts.id) >= 5              -- 그룹 필터: 게시글 5개 이상
ORDER BY post_count DESC;
→ 2024년 2월 이후 가입 + 게시글 5개 이상인 유저 목록
7

서브쿼리

쿼리 안에 쿼리 — WHERE절, FROM절 활용

서브쿼리는 쿼리 안에 중첩된 또 다른 쿼리입니다. 결과를 조건 값이나 임시 테이블로 활용합니다.

WHERE절 서브쿼리 — 단일 값 반환

▶ 실행 예시 — alice가 작성한 게시글의 댓글 모두 조회
SELECT id, content, post_id
FROM   comments
WHERE  post_id IN (
  SELECT id           -- 서브쿼리: alice의 게시글 id 목록
  FROM   posts
  WHERE  user_id = (
    SELECT id         -- 서브쿼리: alice의 id 조회
    FROM   users
    WHERE  username = 'alice'
  )
);
→ alice의 게시글에 달린 모든 댓글 반환

WHERE절 서브쿼리 — 존재 여부 확인 (EXISTS)

▶ 실행 예시 — 댓글을 한 번이라도 작성한 유저만 조회
SELECT id, username
FROM   users
WHERE  EXISTS (
  SELECT 1
  FROM   comments
  WHERE  comments.user_id = users.id   -- 외부 쿼리의 users.id 참조
);
→ 댓글을 한 번 이상 달았던 유저 목록 반환

FROM절 서브쿼리 — 인라인 뷰

FROM절에 넣은 서브쿼리는 임시 테이블처럼 동작합니다. 복잡한 집계 결과를 한 번 더 가공할 때 씁니다.

▶ 실행 예시 — 유저별 게시글 수 중 평균 이상인 유저만
SELECT username, post_count
FROM (
  -- 서브쿼리로 유저별 게시글 수 집계
  SELECT   users.username,
           COUNT(posts.id) AS post_count
  FROM     users
  LEFT JOIN posts ON posts.user_id = users.id
  GROUP BY users.id
) AS user_stats                           -- 인라인 뷰에는 별칭 필수
WHERE post_count > (
  SELECT AVG(post_count)                 -- 전체 평균 게시글 수
  FROM (
    SELECT   COUNT(posts.id) AS post_count
    FROM     users
    LEFT JOIN posts ON posts.user_id = users.id
    GROUP BY users.id
  )
)
ORDER BY post_count DESC;
→ 평균(5개) 이상의 게시글을 작성한 유저와 그 수 반환
💡

서브쿼리가 복잡해지면 CTE(WITH절)로 정리하세요.
WITH user_stats AS (SELECT ...) 형태로 서브쿼리에 이름을 붙이면 훨씬 읽기 쉬워집니다. SELECT 실습 파일에서 더 다룹니다.

8

ORDER BY & LIMIT

정렬과 페이지네이션

ORDER BY는 결과를 정렬하고, LIMIT / OFFSET은 결과의 일부만 가져올 때 씁니다.

ORDER BY — 정렬

▶ 실행 예시 — 다중 컬럼 정렬
-- user_id 오름차순, 같은 user_id 안에서는 created_at 내림차순
SELECT   user_id, id, title, created_at
FROM     posts
ORDER BY user_id ASC,
         created_at DESC
LIMIT    10;
→ 유저 id 순서대로, 같은 유저라면 최신 게시글 먼저 정렬

LIMIT & OFFSET — 페이지네이션

LIMIT n OFFSET m → m번째 행부터 n개 가져오기
1페이지 LIMIT 10 OFFSET 0 → 1~10번째 행
2페이지 LIMIT 10 OFFSET 10 → 11~20번째 행
n페이지 LIMIT 10 OFFSET (n-1)*10 → 일반 공식
▶ 실행 예시 — 게시글 목록 2페이지 (페이지당 10개)
SELECT   posts.id,
         posts.title,
         users.username,
         posts.created_at
FROM     posts
JOIN     users ON posts.user_id = users.id
ORDER BY posts.created_at DESC
LIMIT    10
OFFSET   10;     -- 2페이지: 11~20번째 게시글
→ 최신순 기준 11~20번째 게시글 (2페이지) 반환
⚠️

OFFSET이 크면 느려집니다. OFFSET 10000이라면 앞의 10,000행을 읽고 버리는 방식으로 동작합니다. 데이터가 많을 때는 마지막으로 본 id를 기준으로 WHERE id < 마지막id 방식을 씁니다 (커서 기반 페이지네이션).

마무리 — 전체 패턴 한 눈에

▶ 실행 예시 — 앞서 배운 모든 것을 합친 쿼리
-- 2024년 3월 이후 작성된 게시글 중
-- 댓글이 2개 이상인 것을 게시글 + 작성자 + 댓글 수와 함께 조회
-- 댓글 많은 순, 최대 5개
SELECT   posts.id,
         posts.title,
         users.username             AS author,
         COUNT(comments.id)         AS comment_count
FROM     posts                              -- FROM
JOIN     users    ON posts.user_id  = users.id
LEFT JOIN comments ON comments.post_id = posts.id
WHERE    posts.created_at >= '2024-03-01'  -- WHERE: 3월 이후만
GROUP BY posts.id                           -- GROUP BY: 게시글별
HAVING   COUNT(comments.id) >= 2           -- HAVING: 댓글 2개 이상
ORDER BY comment_count DESC               -- ORDER BY: 많은 순
LIMIT    5;                                  -- LIMIT: 상위 5개
→ 3월 이후 게시글 중 댓글 2개 이상, 댓글 많은 순 상위 5개
