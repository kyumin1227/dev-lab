SELECT の基本構造

クエリを構成する主な句（clause）

SELECT クエリは複数の句で構成されます。最低限必要なのは SELECT と FROMで、ほかは必要なときだけ使います。

SELECT の全体像 
SELECT   カラム1, カラム2, ...      -- ① 取得するカラム（必須）
FROM     テーブル名              -- ② どのテーブルから取るか（必須）
WHERE    条件                  -- ③ 行の絞り込み（任意）
GROUP BY 基準カラム             -- ④ グループ化（任意）
HAVING   グループ条件           -- ⑤ グループの絞り込み（任意）
ORDER BY 並び替え基準         -- ⑥ 並び替え（任意）
LIMIT    n                     -- ⑦ 件数制限（任意）
SELECT
取得するカラムを指定します。* は全カラム、テーブル名.カラム名 と書けば出どころも明確になります。
必須
FROM
データを取得するテーブルを指定します。JOIN を使う場合も、この句でテーブルをつなぎます。
必須
WHERE
条件に合う行だけを残します。GROUP BY より前に実行されるため、集計結果を条件には使えません。
任意
GROUP BY
指定したカラムごとに行をまとめます。COUNT や SUM などの集計関数と一緒に使います。
任意
HAVING
GROUP BY で作られたグループに条件を付けます。COUNT や SUM などの集計結果を条件に使えます。
任意
ORDER BY
結果を並び替えます。ASC は昇順（初期値）、DESC は降順です。
任意
LIMIT
返す行数の上限を指定します。OFFSET n と組み合わせればページネーションにも使えます。
任意

掲示板の例 — いちばん簡単な形から

▶ 実行例 — ユーザー一覧を取得
SELECT id, username, created_at
FROM   users;
→ `users` テーブルの全行から、`id`・`username`・`created_at` の3列を返す
▶ 実行例 — 新しい投稿を5件取得
SELECT   id, title, created_at
FROM     posts
ORDER BY created_at DESC
LIMIT    5;
→ もっとも新しく作成された投稿を5件返す
💡

`SELECT *` はできるだけ避けましょう。 必要なカラムだけ明示すると通信量を減らせて、何のデータを使っているかも一目で分かります。 `users` テーブルで SELECT * を使うと、パスワードハッシュまで一緒に返ってしまいます。

実行順序

書く順番と実際に実行される順番は違う

SQL は 書く順番と実行される順番が一致しません。 ここを理解すると、「なぜ WHERE で SELECT の別名を使えないのか」が自然に分かります。

1
FROM + JOIN
テーブルの選択・結合
2
WHERE
行の絞り込み
3
GROUP BY
グループ化
4
HAVING
グループの絞り込み
5
SELECT
カラム選択・別名付け
6
DISTINCT
重複除去
7
ORDER BY
並び替え
8
LIMIT / OFFSET
件数制限・ページネーション
⚠️

SELECT は5番目に実行されます。 そのため WHERE 句（2番目）では、SELECT で付けた別名（AS）を使えません。ORDER BY は後で実行されるので、SELECT の別名が使えます。

実行順序が大事な理由 — 例で確認

WHERE で SELECT の別名を使うとエラーになる 
-- ❌ エラー: WHERE は SELECT より先に実行されるため、別名をまだ知らない
SELECT COUNT(id) AS cnt
FROM   comments
WHERE  cnt > 5;        -- cnt はまだ定義されていない

-- ✅ 正しい書き方: 集計結果への条件は HAVING に書く
SELECT   post_id, COUNT(id) AS cnt
FROM     comments
GROUP BY post_id
HAVING   COUNT(id) > 5;
▶ 実行例 — コメントが2件以上ある投稿だけを見る
SELECT   post_id,
         COUNT(id) AS comment_count
FROM     comments          -- ① テーブルを選ぶ
--                            ② WHERE なし（全件対象）
GROUP BY post_id           -- ③ 投稿ごとにグループ化
HAVING   COUNT(id) >= 2   -- ④ 2件以上のグループだけ残す
ORDER BY comment_count DESC; -- ⑥ 多い順に並べる
→ コメントが2件以上付いた投稿一覧を、コメント数の多い順で返す
3

WHERE 条件の書き方

比較・論理・パターン・範囲・一覧・NULL の扱い

WHERE 句ではさまざまな演算子が使えます。条件が true になる行だけが結果に含まれます。

比較演算子

演算子 意味 掲示板での例
= 等しい user_id = 1
!= または <> 等しくない user_id != 1
> / >= 大きい / 以上 id > 10
< / <= 小さい / 以下 id <= 50
▶ 実行例 — `user_id` が 1 の投稿だけを取得
SELECT id, title, created_at
FROM   posts
WHERE  user_id = 1;
→ `alice`（id=1）が書いた投稿だけを返す

論理演算子 — AND / OR / NOT

▶ 実行例 — 複数条件を組み合わせる
-- AND: 2つの条件をどちらも満たす行
SELECT id, title
FROM   posts
WHERE  user_id = 1
  AND  id <= 50;

-- OR: どちらか一方でも満たす行
SELECT id, title
FROM   posts
WHERE  user_id = 1
  OR   user_id = 2;
→ 1つ目は「alice が書いた投稿かつ id が 50 以下」、2つ目は「alice または bob の投稿」

LIKE — パターン検索

% は 0 文字以上の任意文字列、_ はちょうど 1 文字の任意文字を意味します。

▶ 実行例 — タイトルに "JOIN" を含む投稿
SELECT id, title
FROM   posts
WHERE  title LIKE '%JOIN%';     -- 前後どこでも JOIN を含む
→ たとえば「JOIN 完全攻略」「NATURAL JOIN 入門」など、タイトルに JOIN を含む投稿
▶ 実行例 — ユーザー名が `a` で始まるユーザー
SELECT id, username
FROM   users
WHERE  username LIKE 'a%';       -- a で始まるすべてのユーザー名
→ `alice` を返す

BETWEEN — 範囲条件

ℹ️

`BETWEEN a AND b` は、`a` 以上 `b` 以下（両端を含む）です。 WHERE id >= 10 AND id <= 20 と同じ意味です。

▶ 実行例 — id が 10〜20 の投稿
SELECT id, title
FROM   posts
WHERE  id BETWEEN 10 AND 20;
→ id が 10, 11, 12 ... 20 の投稿を返す
▶ 実行例 — 2024年2月に作成された投稿
SELECT id, title, created_at
FROM   posts
WHERE  created_at BETWEEN '2024-02-01' AND '2024-02-29 23:59:59';
→ 2024年2月の1か月間に作成された投稿を返す

IN — 一覧条件

IN (値1, 値2, ...) は、一覧のどれか1つに一致する行を返します。OR を何回も書くより簡潔です。

▶ 実行例 — 特定ユーザーたちの投稿
SELECT id, title, user_id
FROM   posts
WHERE  user_id IN (1, 3, 5);    -- alice, carol, eve の投稿
→ `alice`・`carol`・`eve` の3人が書いた投稿を返す（OR を3つ書くのと同じ）

IS NULL / IS NOT NULL

⚠️

NULL は = NULL で比較してはいけません。 NULL は「値がない」を意味するため、比較結果は常に unknown になります。必ず IS NULL か IS NOT NULL を使います。

▶ 実行例 — 考え方の確認（掲示板テーブルには NULL なし）
-- NULL を正しく比較する方法
SELECT id, username
FROM   users
WHERE  created_at IS NOT NULL;  -- created_at があるユーザー

-- ❌ 誤った書き方（常に 0 行になる）
-- WHERE created_at = NULL
→ `created_at` を持つすべてのユーザーを返す（この掲示板では全ユーザー）
4

JOIN の基本原理

複数テーブルのデータを1つに結びつける

投稿テーブルには、作成者を表す user_id（数値）しか入っていません。画面に名前を出したいなら、`users` テーブルと JOIN して取得する必要があります。

JOIN の基本構文 
SELECT ...
FROM   テーブルA
JOIN   テーブルB ON テーブルA.結合カラム = テーブルB.結合カラム
INNER JOIN
🔵🟣🔴 → 🟣
両方のテーブルで一致する行だけを返す
掲示板では、投稿と作成者の両方が存在する場合だけ結果に含まれます。
JOIN とだけ書いた場合も INNER JOIN です。
LEFT JOIN
🔵🟣🔴 → 🔵🟣
左側テーブルの全行を残し、右側に対応がなければ NULL にする
掲示板では、コメントがない投稿も一覧に出したいときに使います。
RIGHT JOIN
🔵🟣🔴 → 🟣🔴
右側テーブルの全行を残し、左側に対応がなければ NULL にする
SQLite は RIGHT JOIN をサポートしていないため、テーブル順を入れ替えて LEFT JOIN で代用します。
CROSS JOIN（注意）
A×B → 全組み合わせ
ON を使わず、2つのテーブルの全組み合わせを作る
users が 20 人、posts が 100 件なら 2,000 行が生成されます。意図せず起きると性能問題の原因になります。

INNER JOIN — 投稿を作成者名つきで取得する

▶ 実行例 — 投稿 + 作成者名（INNER JOIN）
SELECT  posts.id,
        posts.title,
        users.username AS author
FROM    posts
JOIN    users ON posts.user_id = users.id
LIMIT   5;
→ `id`、`title`、作成者名の3列を返す（作成者がいない投稿は除外）

LEFT JOIN — コメント数つき一覧（コメントなし投稿も含む）

▶ 実行例 — 投稿一覧 + コメント数（LEFT JOIN）
SELECT   posts.id,
         posts.title,
         COUNT(comments.id) AS comment_count
FROM     posts
LEFT JOIN comments ON comments.post_id = posts.id
GROUP BY posts.id
ORDER BY comment_count DESC
LIMIT    10;
→ コメント数の多い投稿を上位10件返す。コメントが0件の投稿も `comment_count = 0` として含まれる

3テーブルを JOIN する

▶ 実行例 — コメント + 投稿タイトル + コメント投稿者
SELECT  comments.id       AS comment_id,
        comments.content,
        posts.title          AS post_title,
        users.username       AS commenter
FROM    comments
JOIN    posts  ON comments.post_id  = posts.id
JOIN    users  ON comments.user_id  = users.id
LIMIT   5;
→ コメント内容、対象投稿のタイトル、コメント投稿者名をまとめて取得する

集計関数

複数行を1つの値にまとめる

集計関数は複数行の値を受け取り、1つの値にまとめます。GROUP BY と組み合わせると、グループごとの集計ができます。

COUNT()
行数を数えます。
COUNT(*) は全行、
COUNT(カラム) は NULL を除いた件数です
SUM()
数値カラムの合計を求めます。
NULL は無視されます。
AVG()
数値カラムの平均を求めます。
NULL の行は除外して計算します。
MIN()
最小値を返します。
数値・文字列・日付のどれにも使えます。
MAX()
最大値を返します。
最新の日付を探すときにも使えます。
COUNT(DISTINCT)
重複を除いた一意な値の数を数えます。
▶ 実行例 — 掲示板全体の統計を一度に取得
SELECT
  COUNT(DISTINCT users.id)    AS total_users,    -- ユーザー総数
  COUNT(DISTINCT posts.id)    AS total_posts,    -- 投稿総数
  COUNT(DISTINCT comments.id) AS total_comments  -- コメント総数
FROM      users
LEFT JOIN posts    ON posts.user_id    = users.id
LEFT JOIN comments ON comments.user_id = users.id;
→ `total_users: 20`, `total_posts: 100`, `total_comments: 200`（`seed.sql` 適用時の例）
▶ 実行例 — 最初と最後に登録したユーザー
SELECT
  MIN(created_at) AS first_joined,
  MAX(created_at) AS last_joined,
  COUNT(*)        AS total
FROM users;
→ 最初の登録日、最新の登録日、ユーザー総数を返す
⚠️

`COUNT(*)` と `COUNT(カラム)` の違い
COUNT(*) は NULL を含む全行を数えます。
COUNT(カラム名) は、そのカラムが NULL の行を除いて数えます。
LEFT JOIN の結果で「一致した行だけ」を数えたいなら、必ず COUNT(カラム名) を使いましょう。

6

GROUP BY & HAVING

グループごとの集計と絞り込み

GROUP BY は、指定したカラムの値が同じ行を1つのグループにまとめます。そこへ集計関数を適用すると、 グループごとの統計が作れます。

GROUP BY の動き方

`comments` テーブルを user_id で GROUP BY すると:
GROUP BY 前（一部）
id user_id
1 2
2 3
3 2
4 4
→
GROUP BY 後
user_id COUNT(*)
2 2
3 1
4 1
▶ 実行例 — ユーザーごとの投稿数（多い順）
SELECT   users.username,
         COUNT(posts.id) AS post_count
FROM     users
LEFT JOIN posts ON posts.user_id = users.id
GROUP BY users.id
ORDER BY post_count DESC;
→ 各ユーザーの投稿数を返す。投稿がないユーザーは 0 として表示される

WHERE と HAVING の比較

項目 WHERE HAVING
実行タイミング GROUP BY 前（各行の絞り込み） GROUP BY 後（グループの絞り込み）
使える条件 通常のカラム値 集計関数の結果
例 WHERE user_id = 1 HAVING COUNT(*) > 5
▶ 実行例 — WHERE + GROUP BY + HAVING を一緒に使う
-- 2024年2月以降に登録し、投稿を5件以上書いたユーザー
SELECT   users.username,
         users.created_at,
         COUNT(posts.id) AS post_count
FROM     users
LEFT JOIN posts ON posts.user_id = users.id
WHERE    users.created_at >= '2024-02-01'  -- 行フィルタ: 2月以降の登録者だけ
GROUP BY users.id
HAVING   COUNT(posts.id) >= 5              -- グループフィルタ: 投稿5件以上
ORDER BY post_count DESC;
→ 2024年2月以降に登録し、投稿が5件以上あるユーザー一覧を返す

サブクエリ

クエリの中にもう1つのクエリを書く — WHERE句・FROM句で活用

サブクエリは、クエリの中に入れ子で書かれる別のクエリです。結果を条件値として使ったり、仮のテーブルのように扱ったりできます。

WHERE 句のサブクエリ — 単一値・一覧を返す例

▶ 実行例 — `alice` が書いた投稿のコメントをすべて取得
SELECT id, content, post_id
FROM   comments
WHERE  post_id IN (
  SELECT id           -- サブクエリ: alice の投稿 id 一覧
  FROM   posts
  WHERE  user_id = (
    SELECT id         -- サブクエリ: alice の user id を取得
    FROM   users
    WHERE  username = 'alice'
  )
);
→ `alice` の投稿に付いたコメントをすべて返す

WHERE 句のサブクエリ — 存在確認（EXISTS）

▶ 実行例 — 1回でもコメントしたユーザーだけを取得
SELECT id, username
FROM   users
WHERE  EXISTS (
  SELECT 1
  FROM   comments
  WHERE  comments.user_id = users.id   -- 外側の users.id を参照
);
→ コメントを1回以上書いたことのあるユーザー一覧を返す

FROM 句のサブクエリ — インラインビュー

FROM 句に置いたサブクエリは、一時テーブルのように振る舞います。複雑な集計結果をさらに加工したいときに便利です。

▶ 実行例 — ユーザーごとの投稿数が平均以上の人だけを取得
SELECT username, post_count
FROM (
  -- サブクエリでユーザーごとの投稿数を集計
  SELECT   users.username,
           COUNT(posts.id) AS post_count
  FROM     users
  LEFT JOIN posts ON posts.user_id = users.id
  GROUP BY users.id
) AS user_stats                           -- インラインビューには別名が必須
WHERE post_count > (
  SELECT AVG(post_count)                 -- 投稿数の全体平均
  FROM (
    SELECT   COUNT(posts.id) AS post_count
    FROM     users
    LEFT JOIN posts ON posts.user_id = users.id
    GROUP BY users.id
  )
)
ORDER BY post_count DESC;
→ 平均（5件）以上の投稿を書いたユーザーと、その投稿数を返す
💡

サブクエリが複雑になったら CTE（WITH句）で整理しましょう。
WITH user_stats AS (SELECT ...) のように名前を付けると、かなり読みやすくなります。詳しくは SELECT 演習ファイルで扱います。

8

ORDER BY & LIMIT

並び替えとページネーション

ORDER BY は結果の並び替えに、LIMIT / OFFSET は結果の一部だけを取り出すときに使います。

ORDER BY — 並び替え

▶ 実行例 — 複数カラムで並び替える
-- user_id は昇順、同じ user_id の中では created_at を降順
SELECT   user_id, id, title, created_at
FROM     posts
ORDER BY user_id ASC,
         created_at DESC
LIMIT    10;
→ ユーザー id 順に並べ、同じユーザー内では新しい投稿を先に表示する

LIMIT & OFFSET — ページネーション

LIMIT n OFFSET m → m 行目から n 件を取得
1ページ LIMIT 10 OFFSET 0 → 1〜10行目
2ページ LIMIT 10 OFFSET 10 → 11〜20行目
nページ LIMIT 10 OFFSET (n-1)*10 → 一般式
▶ 実行例 — 投稿一覧の2ページ目（1ページ10件）
SELECT   posts.id,
         posts.title,
         users.username,
         posts.created_at
FROM     posts
JOIN     users ON posts.user_id = users.id
ORDER BY posts.created_at DESC
LIMIT    10
OFFSET   10;     -- 2ページ目: 11〜20件目の投稿
→ 新しい順で見たときの 11〜20 件目の投稿を返す（2ページ目）
⚠️

OFFSET が大きいと遅くなります。 たとえば OFFSET 10000 は、先頭の 10,000 行を読んで捨てる形で動きます。データ量が多い場合は、最後に見た id を基準に WHERE id < 最後のid のように書くカーソル方式がよく使われます。

まとめ — 全体パターンを一目で見る

▶ 実行例 — ここまで学んだ内容をまとめたクエリ
-- 2024年3月以降に作成された投稿のうち
-- コメントが2件以上あるものを、投稿 + 作成者 + コメント数つきで取得
-- コメント数の多い順で、最大5件
SELECT   posts.id,
         posts.title,
         users.username             AS author,
         COUNT(comments.id)         AS comment_count
FROM     posts                              -- FROM
JOIN     users    ON posts.user_id  = users.id
LEFT JOIN comments ON comments.post_id = posts.id
WHERE    posts.created_at >= '2024-03-01'  -- WHERE: 3月以降の投稿だけ
GROUP BY posts.id                           -- GROUP BY: 投稿ごと
HAVING   COUNT(comments.id) >= 2           -- HAVING: コメント2件以上
ORDER BY comment_count DESC               -- ORDER BY: 多い順
LIMIT    5;                                  -- LIMIT: 上位5件
→ 3月以降の投稿のうち、コメントが2件以上あるものをコメント数の多い順で5件返す
